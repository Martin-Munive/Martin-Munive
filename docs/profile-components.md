# Profile Components Architecture

## Decision

The GitHub profile no longer depends on live third-party image endpoints for critical statistics.

The reliable pattern is:

1. Query GitHub from a scheduled GitHub Actions workflow.
2. Generate SVG files inside this repository.
3. Commit those SVG files to `assets/generated/`.
4. Render only local repository assets from `README.md`.

This avoids profile failures caused by public widget rate limits, Vercel/Heroku outages, broken caches, endpoint migrations or HTML error responses returned where GitHub expects an image.

## Applied Components

| Component | Local asset | Source of truth |
|---|---|---|
| GitHub Signals | `assets/generated/github-signals.svg` | GitHub REST + GraphQL API |
| Language Constellation | `assets/generated/top-languages.svg` | Project-normalized signal from GitHub REST language data, with explicit generated-code exclusions |
| Engineering Pulse | `assets/generated/contribution-rhythm.svg` | Twelve-week signal, weekday cadence vector and momentum metrics derived from the GitHub GraphQL contribution calendar |
| Clinical Systems Constellation | `assets/clinical-systems-map.svg` | Curated public portfolio domains and systems |
| Profile Header | `assets/profile-header.svg` | Stable identity, scope and system-focus labels |

The components are generated by `scripts/build_profile_cards.py`.

## Update Policy

The workflow `.github/workflows/profile-components.yml` runs:

- daily at `06:17 UTC`;
- on manual `workflow_dispatch`;
- on pushes that modify the README, the generator script or the workflow itself.

The README does not request dynamic stats from external services at page-render time.

## Counting Rules

- Contribution counts follow GitHub's public contribution calendar rules.
- Private contributions only appear if the GitHub profile settings expose them through the GitHub API.
- The language constellation excludes forks, archived repositories and the profile repository itself.
- Every eligible repository contributes a total weight of one, distributed according to its internal language proportions. Repository size therefore cannot dominate the portfolio signal.
- Repository-specific exclusions are declared in `REPOSITORY_LANGUAGE_EXCLUSIONS`. `Control-insulinas` excludes generated Flutter platform/build languages (`C`, `C++`, `CMake`, Kotlin, Objective-C and Swift) while retaining Dart.
- The asset keeps the historical filename `top-languages.svg` to preserve stable README and workflow links.
- Recently pushed commits may take time to appear in contribution-calendar APIs. The components therefore show generated state, not a real-time event feed.

## Internal Standard

Critical public profile components must be local, generated and versioned.

Remote live images may be used only as decorative badges when their failure does not remove substantive information from the profile.

## Visual System

- Canvas: `#0b1220`; panels: `#111827`; borders: `#243244`.
- Primary text: `#e5edf7`; secondary text: `#94a3b8`.
- Functional accents: cyan for data, green for research/evidence, red for clinical systems and amber for learning.
- Network lines, telemetry and constellations are the shared visual grammar. Mermaid defaults are not used for identity-bearing diagrams because GitHub controls their styling.
- Portfolio links must resolve for anonymous visitors. Private repositories cannot appear as representative public work.
